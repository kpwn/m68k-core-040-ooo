# Serialized normal-write physical bus fault: bounded completion contract

Status: design proposal, **no RTL change**. This proposes an amendment to the precise-store error arm of the selected [July 23 Approach A](2026-07-23-dcache-copyback-store-retirement-design.md), for design review before RTL under `AGENTS.md`. The source audit started at agent68 commit `0f1e4571`; the proposal worktree was based on `f3bd3f2d`. The current outside-default-corpus `format7_normal_write_frame` diagnostic reaches vector 2 with format `$7008` and FA `$AAAA0000`, then fails because WB1S.V is zero; it does not establish that the remainder of this contract works.

## Architectural interpretation and scope

The M68040 manual §2.1 says an instruction finishes execution before its pending memory write-back, which may stall indefinitely. Section 8.4.6.7 says ordinary format-$7 RTE restores the stacked SR/PC and resumes execution; it describes a special mid-instruction continuation for MOVEM, not for an ordinary pending write. The normal-write physical bus-error case in §8.4.6 identifies valid WB1 and equal FA/WB1A. Thus, for **one aligned LONG MOVE store whose physical write was serialized at the ROB head**, the proposed contract is: finish that store's architectural register/CCR effects on B error, expose the failed memory write as WB1 for the handler, stack the macro's sequential next PC, and discard the faulting store and younger work. The handler must complete or deliberately abandon WB1 before RTE; RTE must not secretly replay the store.

This is a bounded machine policy, **not** a universal claim about silicon's stacked PC. Manual §8.2.1 says the saved PC is the instruction executing when the fault is detected and may differ from the bus-cycle initiator because silicon overlaps instructions. Approach A deliberately does not: the precise SQ store waits at the ROB head for B, younger instructions cannot retire, and preemption is interlocked from launch through resolution. For that serialized state, the store is the last architecturally completed instruction even on a physical write error. An independent manual/oracle check of handler-visible An/CCR effects is still needed; §2.1 establishes the stage ordering but does not enumerate every register image on this fault. If that check contradicts the proposed effects, revise this policy before RTL.

Eligibility must be identified from the **real SQ transaction**, not merely vector 2: precise at-head (`!fast`), non-orphan, normal data write, physical B error (`atc=0`), LONG size, naturally aligned address, one beat (`!validB`), macro-last store, and a matching live ROB head ID. Exclude BYTE/WORD stores (raw `datas(head)` is not necessarily the lane-aligned WB1D), DTLB/ATC and earlier address faults, cacheable fast-path asynchronous errors, split stores, RMW/mid-macro stores, MOVE16, MOVEM, cache pushes, FPU writes, and any instruction with pending continuation. The initial target is `MOVE.L (A0)+,(A1)+` and simple aligned LONG MOVE-to-memory forms. A one-beat store can still be part of a larger macro; `p0.last` alone is insufficient to classify it as an ordinary completed instruction, so add an explicit supported-op predicate or prove all included cracks have completed older effects and no continuation. Keep the July failure-sentinel rule: **no successor of the faulting store commits before B or on the error edge**. Good B follows the existing retirement path. No MMU-on cacheable policy changes.

## Existing state and required ordering

`MicroOpAssembler.scala`'s memory-to-memory MOVE crack emits a source load, a source-An update, then a store. The source-An update can retire while the store waits at head. The store µop carries its destination An postincrement and MOVE NZVC, but currently sets `faultUsesNextPc=False`. `LsEuPlugin.scala`'s `pendMem` already holds the store's deferred An/flag writeback; on error its `applyFault` arm sends only SQ completion/fault and discards those effects. The SQ retains `datas`, `vaddrAs`, `sizes`, `supervisors`, and `robIds` until its terminal error pop. The ROB's faulting head does not `retire0`, so its RAT mapping is rolled back on exception squash. `ExceptionUnit.frameWordData` leaves WB1 frame words zero.

The proposed fault transaction has these phases; no phase may publish a successor:

1. **B error capture.** At the SQ terminal `drainAck && drainErr`, capture a one-owner snapshot `{valid, robId, original logical VA, raw data32, size, supervisor, normal-write kind}` while the SQ head is still valid. Retain the present completion/fault pulses and terminal SQ pop. The snapshot may travel over one `LsEuService` Flow to an exception-owned register; document exactly one producer if a `Global` key is introduced. Do not widen every ROB row or each eight-entry pending-store row with a 32-bit data payload. A one-slot snapshot is sufficient only with an assertion that no second live precise fault can overwrite it before the frame is completed; asynchronous fast-path diagnostics remain separate. Orphan completions must consume their pending row but emit no snapshot or architectural effects.
2. **Deferred effect release.** On the matching, non-orphan error apply, release the saved `pendMem` An and NZVC values exactly once through the existing PRF write, wakeup and CCR-completion mechanisms. Keep the SQ fault classification; do not turn this into a success completion or a DTLB fault, and do not duplicate `wbObs`. The effect-write register stage must precede or bypass the fault trigger so its data is physically written and its CCR value is visible when the exception SR is captured. The currently fault-only apply arm is insufficient. X is unchanged for MOVE.
3. **Qualified head commit and exception trigger.** At `headReady && faultRetire && matching snapshot && supported ordinary store`, drive exactly one rename commit for **the faulting head's own** `commitSlotOf(p0)` mapping and old-physical reclamation, then enter vector 2 without ordinary `retire0`/`retire1` or prepared-batch publication. Existing `faultCapPending` must still hold all commits until the dynamic fault record is captured. This commit must precede `excSquash`: `RenameStage` flushes the freelists and drops a same-cycle push, and `RobPlugin`'s commit-versus-flush assertion forbids a commit port while flushing. If exception entry currently asserts `excSquash` combinationally on the trigger edge, add a one-cycle fault-store commit state rather than violating that invariant. Verify `p0.last`, no younger commit lane, exactly-once old-pdst free, and that the pending effects have reached the PRF. The older source-An mapping of memory-to-memory MOVE has already committed; do not commit it again.
4. **CCR and frame.** Fold the faulting store's NZVC into both the exception's stacked SR **and** `committedCcr`, using the live same-cycle `ccrCompletion` bypass if necessary (`RobPlugin`'s `ccrAfter`/`ccrForException` logic). Update only this qualified fault's exception PC to the macro sequential next PC (`p0.predNextPc` for ordinary nonbranch MOVE); do not change all vector-2 PCs or all `faultUsesNextPc` users. Supply format-$7 WB1S.V=1 with normal data write size/type/modifier, WB1A=the original logical store address, WB1D=the raw 32-bit data, and FA=WB1A for the aligned LONG case. Frame offsets are WB1S `+$12` (word 9), WB1A `+$28` (words 20–21), WB1D `+$2c` (words 22–23). Existing SSW/vector and 60-byte frame size stay unchanged. Hold the snapshot through the last frame write, then clear it once. A frame-entry fault or nested fault must not silently overwrite it.
5. **Return.** Ordinary format-$7 RTE reads the handler-edited SR/PC and resumes there. It must not use a hidden pending-store replay token. If the handler repairs the destination and performs WB1, the source read and the store's An/NZVC effects must not happen a second time.

The current ROB exception flow may need a distinct one-cycle qualified commit trigger because `faultRetire` and exception entry are tightly coupled. That timing is an implementation question, not permission to drive `RenameCommitService` during flush. Keep plugin communication through services/`Global`, with one producer per key.

## Evidence and directed acceptance

The first gate is the existing `format7_normal_write_frame` diagnostic: check vector/format, SSW normal write, FA, WB1S.V/size/type/modifier, WB1A and WB1D with distinct address/data; then check that neither the younger failure-sentinel store nor any younger register/CCR write retires. Its present BADF0004 is the missing WB1V, not proof of the proposed commit sequencing.

Add a handler-repair fixture for `MOVE.L (A0)+,(A1)+` with a counted, non-idempotent source read and a B-failing destination. The handler records A0, A1, CCR and stacked PC, repairs or redirects the destination, applies WB1 exactly once from the frame, clears/consumes WB1 as its policy requires, and RTEs. Assert A0 and A1 each advanced once, MOVE NZVC is observed in handler and after RTE, the next macro executes once, source was read once, destination accepted exactly one repaired write, and a younger sentinel never wrote. Use zero, negative and nonzero data values; repeat with no auto-update control. The register/CCR expectations require an external oracle/manual decision before promotion, since the manual's stage narrative is not a complete state table.

Add delayed B/IRQ/trace/debug-preemption edge cases (pre-launch preemption wins; launched drain wins until B), orphan flush and robId reuse, a second would-be fault while the snapshot is held, and prepared-retirement widths 4/8/16. Observe committed RAT/int and NZVC maps, PRF values, freelist old-pdst pushes exactly once, committed CCR shadow, exception SR, and no prepared-map publication on the fault. Distinguish an MMU translation fault before physical issue (no WB1 and faulting-PC restart policy), an ordinary good B (existing behavior), and the MMU-on fast path (asynchronous diagnostic remains). Prove no hidden RTE replay by having the handler edit stacked PC and WB1 fields and checking that RTE follows those edits.

This proposal intentionally leaves BYTE/WORD lane formatting, split writes and multi-access restart unresolved. Manual §8.4.6.4 says a misaligned access FA is the *first byte of the original transfer* regardless of which beat failed; `StoreQueue.sqFaultCompletion.payload.faultAddr` currently selects `vaddrB` when `drainPhaseB` is set. That discrepancy was corrected separately by `1111b8c7` under the amended July 23 contract; focused SQ checks and combined integration gates passed on `113d0d43`. The correction changes FA only and does not implement split pending-write recovery. WB data/byte-lane interpretation for split beats, MOVE16, MOVEM CM continuation and `exc_partial_macro_move_mem_mem`'s general restart policy require separate contracts and tests; they must not inherit this aligned LONG next-PC rule by accident.

Acceptance still requires focused directed tests, default corpus/lockstep, `test-fast`, and area/timing checks before any RTL handoff. This document records a proposed narrow semantic amendment, not a passing implementation.
