# Throughput review against NaxRiscv

**Review date:** 2026-10-01. **Status:** architecture review; no RTL change or spec amendment. **Reference:** [SpinalHDL/NaxRiscv at `9f452d50560d02fb391bc8039f5453c54e0911af`](https://github.com/SpinalHDL/NaxRiscv/tree/9f452d50560d02fb391bc8039f5453c54e0911af), committed 2026-01-23. The comparison is to that revision's `Gen.scala` configuration, not to an unspecified NaxRiscv configuration. Local shipping reference was inspected read-only at `integ/all-shippable` `e98a322c` (`integ2` worktree); this document was written in a reserved review worktree based on `f3bd3f2d`. Several promising flags and branches are still in flight. The 2026-09-29 throughput architecture proposal (`docs/superpowers/specs/2026-09-29-throughput-architecture.md`, currently untracked in the owner's workspace) has not been ratified as a whole; the owner has separately authorized P3 and D-side stage 2. New structural changes beyond that authorized work require a spec update under `AGENTS.md`.

## Verdict

The most valuable NaxRiscv lessons are decoupling *miss ownership* from *cache-array occupancy*, using separate load/store age tracking for controlled memory overlap, and directing fetch early enough that the machine does not spend most cycles empty. This core already has physical rename, a ROB, multiple issue ports, a predictor, an FTQ, speculative wakeup, and a direct I-side L2 port. Rebuilding those from NaxRiscv would duplicate existing machinery. The highest return now is a measured cut to the **8.29-cycle L1 pointer chase** and **21-cycle L2 pointer chase**, followed by a branch-coverage and fetch-continuity rewrite, then multi-miss D-side capacity once the core can supply independent requests. The broad 68k system workload is front-end starved; copy bandwidth is a separate workload with a different bottleneck.

The upstream configuration has a **512-entry BTB, 4 KiB gshare, 16 KiB four-way I-cache, 16 KiB four-way D-cache, two refill slots and two writeback slots** ([`Gen.scala` 113–190, 270–285](https://github.com/SpinalHDL/NaxRiscv/blob/9f452d50560d02fb391bc8039f5453c54e0911af/src/main/scala/naxriscv/Gen.scala#L113-L190)). These are configuration facts, **not** a claim that NaxRiscv achieves a particular IPC or that the same sizes suit this 68k machine. No same-workload, same-memory, same-FPGA performance result was found, so none is inferred.

Nax's early PC reschedule with rename held until commit-time rollback, RAT location selector, allocator checks, and generic performance counters were already identified in the [September comparison](superpowers/specs/2026-09-04-naxriscv-architecture-comparison.md). The two-tier redirect and RAT idea must be assessed against current code and recent P8 evidence; they are not new discoveries. In particular, P8 now shows a **fixed 14-cycle resolve-to-useful-retire chain** for shallow branches, and a speculative redirect cannot erase every stage of that chain. The exception/RTE path may be a larger per-event prize, but its event frequency is unmeasured.

## Staged program

1. **Publish one baseline per workload and configuration.** Record shipping flags and board version with Finder/session, Dhrystone, pure L1/L2/DDR chase, grouped copy and dirty-thrash copy. Separate measured board data from sim. Current [performance queue](PERF_LEVER_QUEUE.md) contains superseded conclusions; its later corrections govern. Use named failures and exact output-data checks, since most existing copy kernels did not check data.
2. **Close work already in flight.** Stage trace → load-to-use cut; P3 frontend; LS-OoO liveness; nonblocking D-cache and fill/dirty ordering. Run the required fast gate for each change and controlled board/post-route measurement through the PM's serialized process. Do not add a second team implementation of these items.
3. **Add only the missing traffic market counters.** Measure independent-miss attempts, same-line merges, blocked younger loads behind unknown stores, writeback victim waits, issue-port saturation, and per-class redirect/exception cycles. Nax's structures become justified only when their customer population is visible in this core.
4. **Update the design for new structural work beyond the authorized P3 and D-side stage-2 slices.** The 2026-09-29 proposal remains unratified as a whole, but the owner separately approved those slices. For later changes such as a second-level TLB or idle CLEAN, specify interface, fault/ordering rules, generation wrap, bypass cancellation, timing comparisons and exact falsifiers in the applicable spec.

**Comparability limits:** NaxRiscv's source establishes mechanism and configuration only. It cannot establish this FPGA's fmax, the 68040's macro-level IPC, or benefit on Mac OS workloads. Its RISC-V decode, page-table semantics and trap model differ materially. All upside values above are hypotheses until controlled paired measurements on this implementation.
